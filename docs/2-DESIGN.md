# Office Team Reporter 디자인 기준

## 확정 브리프

따뜻한 종이 위의 사무실 관제실. 한국어로 읽기 쉬운 UI 셸 안에 Kenney CC0 픽셀 에셋의 2D 탑다운 사무실을 둔다. 인터뷰에서 확정한 회사·직원·대표실·층의 은유를 사용한다. 사용자 업무의 핵심은 현재 진행, 결재 요청, 기획 변경, 완료 일지를 빠르게 구분하는 것이다.

| 용도 | 기준색 |
| --- | --- |
| 종이 배경 | `#f4f1e8` |
| 본문 잉크 | `#172c35` |
| 주 행동·진행 | `#29675c` |
| 주의·결재 | `#bf7839` |

## 화면과 위계

로비는 지붕·간판, 수직 구조 프레임, 큰 창과 실내 공간, 층 번호판, 지상 로비·출입구가 연결된 빌딩 단면도로 읽혀야 한다. 층은 하나의 건물 구조 안에서 프로젝트 선택 버튼으로 동작한다. 창의 밝고 어두움으로 불 켜짐·퇴근 상태를 표현하고 결재 대기·자리 비움을 텍스트와 함께 구분한다. 프로젝트 이름·run·상태는 창 장식보다 선명하게 읽히며, 최근 report 순서에 따른 층 재번호 지정을 피한다. 따뜻한 팔레트와 픽셀 사무실의 분위기를 이어가고 독립 카드나 표를 쌓은 형태는 피한다. 390px 폭에서도 층 정보와 선택 동작을 유지하며 키보드 포커스와 reduced motion을 지원한다.

사무실은 픽셀 무대와 실시간 상태를 함께 보여준다. 대표실의 결재 선택지는 분명한 버튼이며, 기획 변경 공지와 문서 열람, 업무 일지의 마지막 스냅샷이 연결된다. stage, summary, 사용자 할 일, blockers는 일러스트 안에만 숨기지 않는다.

`전체 보기`는 사무실 옆에서 바로 찾을 수 있는 버튼으로 제공한다. 열면 뷰포트 크기의 화면 안에 사무실 전체를 비율에 맞춰 표시한다. 닫기 버튼 또는 Esc로 일반 픽셀 보기로 돌아가며, 포커스는 열었던 버튼에 복귀한다. 일반 보기의 픽셀 크기는 유지한다.

사용자 캐릭터는 `대표 · 나`, 리더 에이전트는 `부장 · leader`로 구분한다. 표시 이름을 바꿔도 owner 식별자와 역할 매핑은 유지한다.

직원 이름·부서·작업과 보고된 `task.model` ID·`effort`, 리뷰 라운드·승인/반려는 DOM 텍스트로 직접 읽을 수 있게 남긴다. 모델 ID와 effort를 직급으로 대체하거나 숨기지 않는다. 직급은 선택적인 보조 정보로만 두고, 모델 또는 effort가 없으면 미보고로 표시하며 추측하지 않는다. 색이나 움직임만으로 상태를 전달하지 않는다. 픽셀은 에셋 렌더링에만 적용하고 긴 한국어 본문은 Apple SD Gothic Neo, Malgun Gothic, Noto Sans KR 순의 한국어 시스템 sans 폴백을 사용한다. 키보드 조작, 명확한 focus, 읽을 수 있는 대비와 `prefers-reduced-motion`을 지킨다. 좁은 화면에서도 결재와 주요 정보에 접근할 수 있어야 한다.

## 구현 계약

React DOM + CSS sprites로 씬을 구현한다. 역할·부서·직급 매핑은 `web/src/roles.json` 데이터가 담당한다. 기본 이동은 직선 CSS transition이며 typing/doze는 CSS keyframes다. 원격 폰트·이미지 생성은 필요하지 않다. Kenney Roguelike Indoors와 Roguelike Characters의 원본 라이선스는 배포 에셋과 함께 보존한다.

이 문서는 확정 브리프이며 픽셀 단위 시안이나 브라우저 검수 통과 기록이 아니다. 실제 구현 토큰은 `web/src/app.css`와 `web/src/office.css`를 함께 확인한다.

## 관련 문서

화면 동작·상태는 [진행 보고와 사무실](requirements/progress-office.md), [결재](requirements/decisions-integration.md), [기획서](requirements/documents.md)를 따른다. 실제 토큰과 레이아웃은 [app.css](../web/src/app.css), [office.css](../web/src/office.css), 역할 데이터는 [roles.json](../web/src/roles.json)에서 확인한다. 별도 HTML 화면 정의서는 현재 없다.
