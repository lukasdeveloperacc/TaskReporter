# 사용자 흐름

터미널이 실행의 주 조종석이며, 사용자는 앱에서 `대표 · 나`로 표시된다. 별도 로그인·계정·권한 분기는 없다. localhost·origin·문서 경계는 [아키텍처](1-SYSTEM-ARCHITECTURE.md)와 [기획서 요구사항](requirements/documents.md)을 따른다. 현재 별도 `screens/` 시안은 없으며 구현 진입점은 [App.tsx](../web/src/App.tsx)다.

## 시작과 관찰

1. [README](../README.md)의 Docker 및 MCP 연결을 마치고 터미널에서 basic-team을 실행한다.
2. 첫 report가 프로젝트와 run을 등록한다. 앱의 `#/` 빌딩 로비에 프로젝트 층이 나타난다. 빈 로비는 첫 보고 대기 안내를 보여준다.
3. 층을 누르면 직접 둘러보기가 활성화된 복도로 진입한다. 가장 최근 활성 run을 선택하고, 활성 run이 없으면 최근 종료 run을 연다. 경로는 `#/run/<run_id>`다. 같은 프로젝트의 활성 run이 여럿이면 선택기로 전환한다.
4. stage·요약·사용자 할 일·막힌 사항과 직원 작업·모델·effort·리뷰를 확인한다. 전체 보기를 열면 사무실 배치를 화면 안에 맞춘다. 닫기·Esc 후 원래 버튼으로 포커스가 돌아간다.
5. 빌딩 로비 버튼으로 프로젝트 선택으로 돌아간다. 자세한 상태 조건은 [진행 보고·사무실](requirements/progress-office.md)에 있다.

## 층 숨김·복원

로비의 층 메뉴 → `이 층 숨기기` → 저장 성공 후 해당 층이 Building과 엘리베이터 목록에서 사라진다. 로비의 `숨긴 층 관리` → 숨긴 프로젝트 확인 → `다시 표시`로 복원한다. 모든 층이 숨겨져도 관리 화면으로 들어갈 수 있다. 저장 실패 시 기존 층 표시와 오류·재시도 경로를 유지한다.

숨긴 프로젝트의 pending 질문은 로비에서 열고 기존 결재 창으로 답한다. 기존 직접 run 링크로 사무실·기록·결재를 열 수도 있다. 새 보고와 새 run은 숨김을 해제하지 않는다. 숨김·복원 시 보이는 층에 연속 번호를 다시 매기며 실제 기록과 프로젝트 파일은 보존한다. 상세 계약·완료 기준은 [층 숨김 요구사항](requirements/progress-office.md#building-층-숨김복원)을 따른다.

## 결정과 변경

대표실 결재 서류 또는 결재 대기 버튼 → 질문·추천 표시 확인 → 선택지 클릭 → 저장·리더 호출 응답 → 창 닫힘 순으로 진행한다. 창만 닫으면 질문은 계속 pending이다. 전송 실패는 창에 표시되고 다시 답할 수 있다. 터미널 답변과 긴 대기 복구는 [결재·실행 연동](requirements/decisions-integration.md)을 따른다.

기획서는 사무실 옆 읽기 전용 패널에서 본다. 에디터에서 수정 → 공지와 열람 내용 갱신 → 다음 report에서 리더가 diff 수신 → 재계획 여부 결재 순으로 이어진다. 접근 불가 경로는 열람·변경 감지 불가로 표시한다.

## 종료와 실패 복구

완료·중단 report → 남은 pending 결재 종료 → 업무 일지 → 해당 run의 마지막 작업·리뷰·결정 스냅샷 열기 순으로 확인한다. 진행 중 30분 무보고는 자리 비움이며 종료가 아니다. 새 report로 복귀한다.

상태 로딩 실패는 오류와 다시 불러오기를 제공한다. SSE 재연결 시 상태를 다시 읽는다. 잘못되거나 존재하지 않는 run 경로는 로비로 표시한다. Office 연결 장애 시 터미널 스킬은 원본 basic-team HTML 진행 화면으로 전환한다. 질문·상태 복원 규칙은 [실행 연동](requirements/decisions-integration.md)에 있다.

## 직접 둘러보기

엘리베이터 클릭 이동·층/run 전환의 보기 모드 유지는 로컬 구현 상태이며 UI 대상 검사 4개 파일·80개 테스트를 통과했다. 전체 검사·독립 리뷰·브라우저 검증은 진행 중이다. 아래 기존 흐름의 완료 이력과 구분하며 [UI 요구사항](requirements/progress-office.md#엘리베이터-클릭-이동과-보기-모드-유지)과 [변경 010](changes/010-agent-check-ins.md)을 따른다. 현재 흐름은 엘리베이터 클릭 → 대표가 지도 경로로 이동 → 도착 후 층 선택 → 목적지 도착 순서다. 이동 중 중단·경로 실패·층/run 전환으로 취소되면 이전 이동의 창이 뒤늦게 열리지 않는다. 층 선택의 현재 층·빈 층 차단, 실패 안내와 키보드·포커스 규칙은 유지한다.

보기 모드 정책은 전체 보기로 층/run을 바꾸면 전체 보기를, 일반 보기로 바꾸면 일반 보기를 유지하는 것이다. 이전 층의 상세·이동 상태는 정리하고 새 층 도착 위치와 카메라를 맞춘다. 새로고침 저장 복원이나 디자인 변경은 범위 밖이며 결재의 기존 전체 보기 닫기 규칙은 유지한다. 실제 브라우저 E2E·Impeccable 검증 전이다.

기본 직접 둘러보기는 실제 브라우저 검증과 독립 리뷰를 마쳤다. 전체 보기 이동·상호작용과 직원 업무 기록·추가 단축키도 구현 및 자동·실제 브라우저 검증을 마쳤으며 결과는 [변경 기록 003](changes/003-overview-visitor.md)에 있다. 복도·출입문 탐색은 [변경 기록 006](changes/006-door-corridor.md)에 따라 구현·자동 검증과 2026-10-20 R1 실제 데스크톱·모바일 브라우저 검증을 완료했다. R1 코드 리뷰의 필수 보강 3건도 수정 완료했고 최종 자동 검사는 18개 파일·120개 테스트를 통과했다. 자세한 결과는 변경 006에 기록하며 수정 후 최종 동일본 검토는 실행 진행 기록에서 관리한다. 세부 입력·포커스·예외 조건은 [진행 보고·사무실](requirements/progress-office.md#직접-둘러보기)을 따른다.

1. 유효한 층에 진입하면 별도 활성화 클릭 없이 엘리베이터 앞 복도에서 시작한다. 직접 run URL의 초기 로딩 뒤에도 동일하다. 지도 포커스 → 방향키·WASD 또는 화면 방향 버튼으로 이동 → 팀 방향 표지와 미니맵으로 목적지 확인 → 문 가까이에서 Enter → 해당 팀 방 하나로 입장한다. 일반 보기에서 문 틈은 걷기만으로 통과할 수 없다. 부서 바로가기는 문 방향 안내 대상을 정하며 이동시키거나 일시정지하지 않는다. 복도에서는 닫힌 방 외관을, 내부에서는 현재 방의 실제 직원·책상·업무 표시와 출구만 본다.
2. 직원에게 접근 → Enter로 화면 중앙의 큰 보고 창에서 현재 업무 읽기 → Enter로 작업 기록 → Enter로 닫고 지도 포커스·이동 재개 순으로 확인한다. 중앙 보고 창은 변경 005에 구현했으며 모바일에서도 화면 안에 맞추고 긴 내용은 창 안에서 스크롤한다. 창이 열리면 어두운 배경으로 구분하고 Tab 포커스를 창 안에서 순환시킨다. 배경 클릭으로는 닫지 않는다. 이 Enter 중심 흐름과 자동 검증 결과는 [변경 004](changes/004-elevator-keyboard.md)에 있다. E·살펴보기, J 기록, 보고 안 R·J·키보드 탭은 선택적인 조작으로 유지한다. 보고 창의 Esc 닫기 안내에 따라 Esc를 누르면 보고 창만 닫고 전체 보기를 유지한다. Esc·닫기 버튼도 이전에 걷던 상태와 지도 포커스를 복구해 별도 재개 없이 이어간다. 구현·자동 검증 결과는 [변경 005](changes/005-continuous-visitor.md)에 있다. 보고를 보는 중 직원이 사라지거나 run이 종료되면 이용 불가 안내와 닫기 버튼 포커스로 복구한다. 기록은 현재·활성·보관·종료 run과 완료 작업을 포함하고 최신 유효 보고·종료 시각 순으로 정렬한 스냅샷이며 터미널 로그가 아니다.
3. 방 출구에서 Enter → 같은 문 바깥 복도로 복귀 → 엘리베이터 접근 → E·Enter 또는 상호작용 버튼 → 실제 프로젝트 층 선택 → 목적지 최근 활성 run 또는 최근 종료 run → 엘리베이터 도착·목적지 보고 확인 순으로 이동한다. 현재 층·빈 층은 선택할 수 없고 사라진 목적지는 안내 후 현재 층에 머문다. 창을 열면 첫 선택 가능한 목적지에 포커스를 두고, 방향키·Home/End로 활성 버튼을 탐색한 뒤 Enter·Space로 실행한다. 목적지가 없으면 로비 버튼에 포커스를 둔다. Esc는 창만 닫고 지도 포커스와 기존 전체 보기를 유지하며, 변경 005에 따라 이전 이동 상태로 돌아간다. 성공한 층 이동도 도착 후 이동을 계속하고 실패하면 선택 창·오류 안내에 머문다. 이 키보드 탐색도 구현과 자동 검증을 마쳤다.
4. 직원 패널 R·J는 한글 자판의 같은 물리 키로도 동작한다. 지도에 포커스가 있을 때 F로 전체 보기를 전환하고 Space로 일시정지·재개한다. Esc·일시정지로 멈춘 뒤 재개 버튼도 사용할 수 있다. 전체 보기에서는 기존 열 개 방과 실제 직원의 전체 지도를 유지하며 방향키·WASD·화면 버튼으로 기존 문 틈을 지나 이동하고 직원 상세·엘리베이터를 연다. 전환 시 대표 위치를 보존하고 일반 보기 복귀 시 실제 위치에 맞는 방 또는 복도를 표시한다. 미니맵은 실제 대표 위치·현재 방·안내 목적지를 보여주며 클릭 이동 기능은 없다. 전체 배치는 유지하며 지도 배경 클릭으로 지도 포커스를 되찾고 일시정지·재개 버튼도 사용할 수 있다. 전체 보기 안에서 방문 패널의 Esc는 해당 패널만 닫고, 방문 패널이 없으면 전체 보기를 닫는다. 결재는 이동을 멈추고 방문 패널·전체 보기를 닫는다. 결재 창의 포커스·Esc가 우선하며 닫힌 뒤 자동으로 걷지 않는다.
5. 층·run·hash 변경 시 이전 상세·선택 결재를 정리하며, 프로젝트가 달라지면 이전 업무 일지 스냅샷도 닫는다. 다른 유효 층 진입과 로비에서의 재진입은 둘러보기를 활성화한다. 로비 이동·로딩이 끝난 잘못된 경로·끝내기는 종료한다. 끝내기는 같은 run의 보고 갱신에도 유지하며 `직접 둘러보기`로 다시 시작할 수 있다. 새로고침으로 유효한 층에 진입할 때도 기본 활성화한다.
