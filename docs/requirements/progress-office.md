## 계약과 업무 규칙

`POST /mcp`의 `report`는 절대 `project_path`, `patch`와 선택적인 `run_id`, `doc_path`, `title`, `close_ask_ids`, `check_replies`를 받는다. 새 실행은 run_id를 발급하고 기존 실행은 같은 id로 이어간다. 다른 프로젝트에 속한 run_id나 알 수 없는 id는 오류이며 자동으로 새 run을 만들지 않는다. 응답은 `{run_id, doc_changes, state, ended_at, checks}`이며 state는 병합된 진행 상태다. 정확한 타입은 [contract.ts](../../shared/contract.ts), 검증·병합은 [progress.ts](../../server/progress.ts)를 따른다.

체크인 확장은 로컬 구현되었으며 전체 검사·독립 리뷰는 진행 중이다. 선택적인 최상위 `check_replies: [{check_id, answer}]`와 `report.checks`(pending), 읽기 전용 `get_run.checks`(전체 이력)를 추가한다. model·effort 누락은 보고를 거부하는 대신 즉시 확인 요청을 만들며, 값 보충만으로 업무 진척·명시 응답으로 보지 않는다. 기존 필수 입력과 progress 병합 결과는 유지한다. [체크인 요구사항](decisions-integration.md#에이전트-체크인)에서 정체 기준·수명주기·쿨다운·오류를 관리한다.

- 텍스트 patch는 title·stage·summary·todo·blockers만 받는다. task는 id, decision은 앞뒤 공백을 제거한 title, review는 round+reviewer로 병합한다. 보내지 않은 기존 항목을 보존한다.
- stage는 계획·구현·리뷰·수정·마무리·완료·중단으로 시작한다. task lane은 plan/build/review/fix/finish, status는 대기중·진행중·완료·중단이다. after는 존재하는 task id만 참조한다.
- 진행중 진입과 완료·중단 전환 때 task 시간을 기록한다. 열린 task가 있으면 완료 report를 거부한다. finish 종료의 자동 stage 규칙은 원본 progress.py와 맞추며 아래 미완료 TODO 성공 종료 검증을 추가한다.
- review 이름은 Karpathy Agent, Ponytail Agent, Impeccable Agent, E2E Agent다. 라운드와 보고된 판정·note를 표시한다.

### MCP 입력 검증·조회 개선

상태: 구현·자동 검증 완료. 결과는 [변경 008](../changes/008-mcp-validation.md)에 기록한다.

- 도구 인자 최상위와 patch·중첩 항목을 strict 스키마로 검증하여 `close_asks` 같은 오타를 버리지 않고 오류로 반환한다. `close_ask_ids`는 patch 안이 아닌 최상위 인자다. 기존 `patch.title`은 유지한다.
- task 허용 필드는 `id`, `title`, `owner`, `model`, `effort`, `lane`, `status`, `after`, `note`, `todos`다. decision은 `title`, `body`, review는 `round`, `reviewer`, `verdict`, `note`만 받는다. patch에는 이 배열들과 `title`, `stage`, `summary`, `blockers`, `todo`를 허용한다. lane·status·reviewer의 값은 공용 계약의 enum을 따른다. 각 필드 설명을 MCP 스키마에 노출한다.
- model은 전체 모델 ID를 기록한다. effort는 host가 확인한 값(예: low·medium·high)을 보내며 모르면 생략한다. owner가 사무실 좌석을 결정하고 `reviewer-*`는 감사팀, `plan-*`는 회의실로 배치한다. tasks 없이 reviews만 보고해도 리뷰어 캐릭터를 표시한다.
- 첫 report로 받은 run_id를 이후 호출에 재사용한다. stage 접두어와 기존 병합 키(task id·decision title·review round+reviewer)는 유지한다.
- 읽기 전용 `get_run({run_id})`은 project_path·stage·ended_at·tasks·decisions·reviews와 pending 질문 목록인 asks를 반환한다. MCP `readOnlyHint`를 선언하며 조회로 실행을 생성하거나 변경하지 않는다.
- TypeScript 병합 경로도 task·decision·review의 허용 키 외 필드를 거부한다. HTML 원본 progress.py 자체는 수정하지 않으며 기존 병합·시간·종료 규칙과의 호환을 유지한다.

완료 기준은 실제 tools/list의 필드 설명·strict 스키마·읽기 전용 선언, 오타 거부와 저장 전 검증, report 응답 상태, get_run 조회와 pending 질문, owner 좌석·reviews만 있는 캐릭터를 자동 검증하는 것이다. 전체 test·typecheck·build·원본 golden을 통과해야 한다. 실제 Claude Code 클라이언트 검증과 SDK 도구 호출 검증은 구분한다.

### 작업별 Phase TODO

상태: 구현·자동 검사·실제 브라우저 검증 완료. 결과는 [변경 009](../changes/009-task-todos.md)에 기록한다.

task에 선택 필드 `todos`를 추가한다. 각 항목은 비어 있지 않은 문자열 `id`와 선택 필드 `text`, `phase`, `done`, `detail`만 받으며 알 수 없는 키는 거부한다. text·phase·detail은 문자열, done은 boolean이다. 같은 task 안에서 todo id로 부분 병합하고 보내지 않은 기존 todo와 필드는 보존한다. 최초 등장 순서를 유지하며 새 todo의 text가 없으면 id를 표시한다. report의 병합된 state와 get_run의 tasks에도 이 목록을 반환한다. 기존 최상위 `todo` 문자열은 유지한다.

직원 현재 업무는 해당 owner의 계획·대기 작업도 포함하며, 현재 업무와 작업 기록 모두 Phase TODO의 완료 표시·진행률 막대와 기본 접힌 detail을 보여준다. 완료 표시는 보고 상태를 읽는 용도이며 앱에서 원본 상태를 수정하지 않는다. note는 줄바꿈 또는 ` · ` 구분자로 나눠 읽기 쉽게 표시한다. 업무 보드에는 TODO 완료 개수/전체 개수(x/y)를 표시한다. todos가 없는 기존 작업도 계속 읽을 수 있어야 한다.

완료 기준은 TODO 부분 병합·순서·필드 보존·기본 text, 타입·알 수 없는 키 거부, report/get_run 노출, 계획·대기 작업과 현재/기록 TODO·detail·진행 표시, note 분리와 기존 작업 호환을 검증하는 것이다. 외부 progress.py와 기존 golden fixture는 변경하지 않는다.

#### 진행 중 TODO와 TODO 갱신 유도

로컬 구현·검증 상태다([변경 019](../changes/019-todo-progress-nudge.md)). TODO는 실제 진행 순서로 정의한다는 전제로, 업무기록은 상태가 `진행중`인 작업의 첫 미완료 TODO에 "진행 중" 표시(굵은 글씨·배지·체크 아이콘 이름 `진행 중`)를 한다. 다른 작업과 대기·완료 작업에는 표시하지 않는다. 새 TODO 필드는 추가하지 않는다.

report 응답 `open_todos`는 이번 patch.tasks에 포함된 작업 중 미완료 TODO가 남은 것의 `{task_id, open, next:{id,text}}`이며 `include_state:false`에서도 제공한다. 진행중 작업의 status·owner·note가 바뀌는 report에서 그 작업의 TODO 변경(체크·추가·문구 수정 모두 포함)이 15분(`TODO_STALE_MS`) 이상 없으면 체크인 질문을 `15분째 TODO 체크 없음:`으로 시작해 만든다. 기준 시각은 처음 관찰, 담당자 변경, run 재개, 작업이 다시 `진행중`이 되는 report에서 새로 시작한다(비활성 동안의 TODO 변경은 추적하지 않음). pending·쿨다운·종료 규칙은 기존 체크인과 같아서, 답한 뒤에도 TODO를 체크하지 않으면 30분 쿨다운 후 다시 물을 수 있다. 서버는 TODO가 done이 된 시각과 작업 완료와 같은 report에서 체크됐는지를 run.state 밖(DB)에 기록해 `get_retros.signals`의 `todos_ticked`, `todos_ticked_at_close`로 보여 준다. 체크 해제 시 기록을 지운다. run.state와 progress.py golden은 바꾸지 않는다.

#### 미완료 TODO의 성공 종료 방지

상태: 로컬 구현·backend 대상 검사 완료. 전체 검사·독립 리뷰는 진행 중이다. [변경 010](../changes/010-agent-check-ins.md)의 추가 범위이며 위 변경 009의 완료 기록과 구분한다.

병합 후 `task.todos`에서 `done !== true`인 항목은 모두 미완료다. done 생략도 미완료이며 TODO가 없는 작업에는 추가 조건이 없다. task의 최종 status가 `완료`이면 자기 TODO가 하나라도 미완료인 report를 거부한다. 이미 완료된 task에 새 unchecked TODO를 추가하거나 완료 TODO를 해제하는 보고도 같은 검증을 받는다. 실제 일을 마치고 같은 patch에서 TODO를 `done:true`로 병합한 뒤 task 완료를 보고할 수 있다.

명시적인 `stage: "완료"`와 finish 작업 종료가 자동으로 만든 최종 stage `완료`는 모든 task의 TODO를 검사한다. status가 `중단`인 task도 미완료 TODO를 성공한 run 안에 숨길 수 없다. 기존 열린 task가 있으면 완료를 거부하는 규칙도 유지한다. finish의 자동 stage 전환은 기존 규칙을 따르되 이 TODO 성공 검증을 추가한다.

run stage `중단`은 미완료 일을 남긴 명시적인 비성공 종료로 허용한다. 서버가 TODO를 자동 체크하거나 성공을 주장하지 않는다. 다만 stage가 중단이어도 task 자체를 `완료`로 보고하면 그 task의 자기 TODO 완료 조건은 적용한다. 새 TODO 필드·취소 endpoint·최상위 자유문자열 `todo` 해석은 추가하지 않는다.

검증 기준은 done false·생략인 자기 TODO의 task 완료 거부, 완료 task의 미완료 항목 추가/해제 거부, 같은 patch의 실제 TODO 완료+task 완료 허용, 명시/자동 run 완료에서 중단 task를 포함한 미완료 TODO 거부, 미완료 없는 기존 작업 호환, run 중단 허용과 자동 체크 없음이다. 거부된 report는 진행 상태·체크인 응답·ask 종료를 포함한 저장을 남기지 않아야 한다. 오류는 `task <task_id>: unfinished TODOs: <todo_ids>` 또는 `run stage 완료 has unfinished TODOs: <task_id>: <todo_ids>; resolve them or interrupt the run`이며 여러 task 목록은 세미콜론으로 연결한다.

## 화면·상태

프로젝트 경로 순으로 빌딩 층을 정렬한다. 보고 도착 순서만으로 층을 재배치하지 않는다. 신규 프로젝트 추가 시 층 번호는 달라질 수 있다. 층은 지붕·간판·구조 프레임·창·지상 출입구가 이어진 하나의 빌딩 안에서 선택한다. 상태는 활성 run 없음 → 퇴근, pending 결재 있음 → 결재 대기, 활성 run 중 마지막 report가 30분 넘은 것이 있음 → 자리 비움, 나머지 → 불 켜짐 순으로 결정한다.

사무실에는 `대표 · 나`와 `부장 · leader`, 부서별 직원·임시 역할 자리를 둔다. owner 식별자를 보존하며 보고된 `task.model` ID와 effort를 DOM 텍스트로 보여준다. 누락 값은 미보고이며 추측하거나 직급으로 대체하지 않는다. stage·summary·todo·blockers도 일러스트 밖에서 읽을 수 있다. 전체 보기는 원래 픽셀 크기의 일반 보기와 별개로 전체 배치를 화면에 맞추며 닫기·Esc·포커스 복귀를 지원한다.

완료·중단 실행은 업무 일지에 남고 마지막 작업·리뷰·결정을 연다. 이는 마지막 스냅샷이며 전체 이벤트 재생이 아니다.

## Building 층 숨김·복원

상태: 구현·자동 검증 완료. 범위와 자동 검사 결과는 [변경 기록 007](../changes/007-floor-visibility.md)에 기록하며, 독립 리뷰·브라우저 검증의 revision별 결과는 실행 진행 기록에서 관리한다.

프로젝트 단위로 층을 숨긴다. 각 층 메뉴의 `이 층 숨기기`로 Building과 직접 둘러보기 엘리베이터의 층 목록에서 제외하고, 로비의 `숨긴 층 관리`에서 `다시 표시`로 복원한다. 모든 층이 숨겨져도 관리 진입점을 제공한다. 표시할 프로젝트만 경로 순으로 정렬하고 1층부터 연속 번호를 계산한다. 숨김·복원 또는 프로젝트 추가 시 보이는 층 수에 맞춰 로비와 엘리베이터의 번호를 함께 다시 매긴다. 표시 프로젝트 집합이 같은 보고 갱신은 번호를 바꾸지 않는다.

숨김 상태는 서버에 저장하며 새로고침·서버 재시작 후 유지한다. 프로젝트·run·질문/답변·기획서 연결과 실제 프로젝트 파일은 보존한다. 숨긴 프로젝트에서 종료되지 않은 작업의 report가 성공하면 기존 run·새 run 모두 자동으로 다시 표시한다. 종료된 기록 갱신과 실패한 report는 숨김을 유지한다. 상태 snapshot에는 숨긴 프로젝트와 기록을 포함한다. 숨김은 접근 제어가 아니며 기존 직접 run 링크와 사무실의 결재 접근은 유지한다.

숨긴 프로젝트의 pending 질문은 로비에서도 열고 답할 수 있어야 한다. 모든 층을 숨긴 상태에서도 이 경로를 유지한다. 표시 상태 저장에 실패하면 기존 표시 상태와 재시도 경로를 유지하고 오류를 안내한다. 오래 열려 있던 엘리베이터에서 이미 숨겨진 목적지를 선택하면 최신 상태를 확인하고 이동하지 않는다.

API는 `PATCH /api/projects/visibility`에 `{project_path: string, hidden: boolean}`을 보낸다. project_path는 비어 있지 않은 문자열이고 hidden은 boolean이어야 한다. 성공은 `200 {ok:true}`, 입력 오류는 400, 미등록 프로젝트는 404이며 이 요청으로 프로젝트를 등록하지 않는다. 변경 후 기존 SSE changed 알림으로 상태를 갱신한다. `ProjectView.hidden`은 기존 fixture 호환을 위해 선택 필드이지만 서버는 boolean을 반환하며 누락 값은 표시 상태로 취급한다.

완료 기준은 숨김·복원, 모두 숨김 복구, 번호 안정성, 표시 저장 실패·재시도, 숨긴 프로젝트 질문 응답, 직접 링크 유지, 엘리베이터 제외·오래된 선택 차단이다. 기존 DB 마이그레이션·재개방과 진행 중 report 자동 복원·종료 report 숨김 유지·실패 시 원자성·기록 보존을 자동 검증한다. 한국어·기존 밝은 테마의 1440×900과 390×844 브라우저에서 주요 화면·대화상자·실패 경로를 확인한다. 영구 삭제·자동 숨김·일괄 숨김은 범위에서 제외한다.

## 직접 둘러보기

기본 구현과 검증 결과는 [변경 기록 002](../changes/002-keyboard-visitor.md)에 기록한다. 기존 전체 보기·직원 업무 기록·추가 단축키의 구현·검증 결과는 [변경 기록 003](../changes/003-overview-visitor.md)을 따른다. 현재 탐색 계약은 아래 복도·출입문 요구사항과 [변경 기록 006](../changes/006-door-corridor.md)이 우선한다. 변경 002~005는 당시 결과로 보존한다.

- 유효한 프로젝트 층과 직접 run URL에 진입하면 별도 활성화 클릭 없이 기존 `대표 · 나` 한 명을 조작한다. 시작·끝내기 전환 버튼은 없다. 사무실 지도에 포커스가 있을 때 방향키 또는 WASD로 24px씩 이동한다. 수정 키·한글 조합 중 입력·입력창과 버튼에서 발생한 키는 이동에 사용하지 않고 Tab은 다음 컨트롤로 이동한다. 일반 관찰 모드의 방향키 스크롤은 유지한다.
- 상단 부서 바로가기, 방 제목 버튼, 지도 문 버튼은 모두 선택한 방 안의 목적지까지 `findVisitorPath`로 대표를 걷게 한다. 모든 역할 데이터에 정의된 방(회의실·대표실·부서·임시 자리 포함)을 지원한다. 새 목적지를 고르면 이전 경로를 바꾸고, 일시정지 중 고르면 이동을 재개한다. 수동 이동·일시정지·Esc·결재·방문 창·층 전환은 진행 중인 목적지를 취소한다. 도착하면 해당 방의 직원·책상·업무가 보인다. 경로를 찾지 못하면 방 이름을 포함한 안내를 표시한다. 자동 걷기·간결한 지도 조작의 구현 상태와 독립 리뷰·실제 브라우저 검수는 [변경 013](../changes/013-room-navigation.md)을 따른다.
- 사무실의 실제 부서 사각형에서 벽과 하단 중앙 출입구를 함께 계산한다. 대표의 발 위치와 작은 충돌 영역으로 지도 경계·벽 통과를 막는다. 일반 보기에서는 문 틈도 걷기만으로 통과할 수 없고 가까운 출입문에서 Enter로 출입한다. 전체 보기의 기존 벽·문 틈 이동 규칙은 유지한다. 책상·직원은 이번 범위의 충돌 대상이 아니다. 엘리베이터와 도착 위치는 부서 밖 아래쪽 통로에 배치한다. 지도 높이는 화면에 남은 높이로 제한하며, 지도 자체가 화면 아래에 있으면 0으로 접히지 않도록 최소 표시 공간을 유지한다. 페이지 스크롤·창 크기·패널 배치 변경 때 다시 측정하여 화면 안으로 돌아왔을 때 높이를 복구한다. 새 층 도착 시에는 목적지 지도의 높이가 반영된 뒤 카메라를 맞춘다. 둘러보기 지도에는 크기 전환 효과를 적용하지 않아 감소된 모션 설정에서도 높이 변경과 도착 카메라가 어긋나지 않게 한다. 카메라는 대표의 전체 표시 영역을 기준으로 사무실 스크롤 영역 안에서 즉시 따라가며 바깥 페이지는 이동시키지 않는다. 창 크기가 바뀌어도 다시 맞추되 일시정지·전체 보기·결재·방문 패널이 열린 동안에는 따라가지 않는다.
- 일반 보기에서는 가까운 출입문이 상호작용 우선 대상이다. 문이 없으면 현재 방의 직원 또는 복도의 엘리베이터에서 E·Enter·화면 상호작용 버튼을 사용한다. 다른 방이나 벽 너머 직원은 선택하지 않는다. 전체 보기에서는 기존 거리 120px 안의 엘리베이터 우선·가장 가까운 직원 선택을 유지한다. 같은 거리면 owner 이름으로 결정한다. E·Enter 반복 입력은 창을 다시 열지 않는다. 가까운 직원의 J 키는 작업 기록을 연다. 엘리베이터 E·Enter는 기존 실제 층 이동을 유지한다.
- 엘리베이터는 로비와 같은 프로젝트 경로 정렬·층 번호를 사용한다. 실제 프로젝트 이름·상태를 표시하며 현재 층과 run 없는 층은 선택할 수 없다. 선택 시 최근 활성 run, 없으면 최근 종료 run으로 이동하고 새 층 엘리베이터에 도착한다. 사라졌거나 비어 버린 목적지는 현재 층에 머물며 안내한다. 빌딩 로비로 나가면 둘러보기를 끝낸다.
- 직원 상세는 실제 owner, 부서, 작업 제목·id, 경과 시간·상태, 보고된 model·effort를 보여준다. 누락 값은 `미보고`, 현재 작업이 없으면 작업 없음으로 표시한다. owner 기준으로 최신 보고를 반영하며 직원이 사라지거나 run 종료로 퇴근하면 이용 불가 안내를 표시하고 직원 패널의 닫기 버튼으로 포커스를 옮긴다. 선택된 보고 탭이 사라져도 키보드로 닫을 수 있다. 종료 run은 종료 표시와 빈 사무실로 탐색하며 직원을 되살리지 않는다. 표시 좌표와 상호작용 좌표를 공유하고 둘러보기 중 직원 위치 전환 효과를 끈다.
- 직원 보고 패널은 owner·부서·직원 상태를 유지하며 R은 현재 업무, J는 작업 기록으로 전환한다. 현재 업무는 선택한 run에서 owner가 정확히 일치하고 상태가 진행중인 작업만 표시한다. 두 화면은 키보드로 선택할 수 있는 이름 있는 탭으로도 제공한다. 좌우 방향키와 Home·End로 탭을 전환하며 R·J는 한글 자판에서도 물리 키 위치로 동작한다. 기록은 같은 프로젝트의 실제 run들에서 owner가 정확히 일치하는 작업을 모으며 현재·활성·보관·종료 run의 모든 해당 작업을 포함하고 유효한 최근 보고·종료 시각 중 최신 값을 기준으로 run을 정렬한다. 완료 작업도 제외하지 않는다. 제목·id·상태·note·model·effort·시작·종료 시각·경과 시간은 실제 보고 스냅샷을 근거로 표시한다. 경과 시간은 유효한 시작 시각부터 종료 시각 또는 현재 시각까지 계산하며 계산할 수 없으면 미보고다. 누락 값은 미보고 또는 없음으로 표시하고 터미널 출력·추측한 작업 이력을 만들지 않는다.
- 지도에 포커스가 있을 때 F는 전체 보기를 전환하고 Space는 일시정지·재개한다. 입력 가능 요소·하위 컨트롤의 키 입력, 수정 키·조합 입력은 소비하지 않는다. 반복 이동은 허용하되 E·Enter·J·F·Space 같은 동작 키의 반복 이벤트는 무시한다. 직원 패널의 R·J도 입력 요소·수정 키·조합·반복 이벤트를 무시한다. 키보드·화면 조작은 간결하게 유지하고 큰 설명 패널은 두지 않는다.
- 지도 Esc·Space·일시정지 버튼으로 수동 정지한 경우는 명시적으로 재개한다. 직원 상세·엘리베이터는 열린 동안만 이동을 막고 Esc·닫기·Enter 완료 뒤 이전 이동 상태로 돌아간다. 구현·자동 검증 결과는 아래 변경 005를 따른다. 전체 보기에서는 전체 지도를 맞춘 채 방향키·WASD와 화면 방향 버튼으로 이동하고 E·Enter·살펴보기로 직원 상세·엘리베이터를 연다. 전체 보기를 이유로 이동을 일시정지하거나 핵심 조작부를 숨기지 않는다. 카메라는 대표를 따라가지 않고 전체 배치를 유지한다. 전체 보기에서 지도 배경 클릭은 지도 포커스를 복구한다. 전체 보기 안에서 상위 방문 패널이 열렸다면 Esc는 그 패널만 닫고 전체 보기를 유지한다. 방문 패널이 없는 전체 보기의 Esc는 전체 보기를 닫고 원래 버튼으로 포커스를 돌려준다. 결재가 열리면 방문 패널·전체 보기를 닫고 결재 창만 포커스를 소유한다. 이동·상호작용 버튼에도 동일한 차단 규칙을 적용한다.
- 엘리베이터는 초기 포커스·Tab 순환·Esc·명시적 닫기를 가진 모달이고 직원 상세는 화면 중앙의 이름 있는 큰 모달이며 dialog 역할과 모달 상태를 제공한다. 배경을 어둡게 하고 배경 클릭으로 닫지 않으며 모달 안에서 Tab·Shift+Tab 포커스를 순환시킨다. 데스크톱은 폭 960px을 기준으로 화면 가장자리에서 16px 이상 떨어지도록 맞추고 최대 높이 85dvh 안에서 긴 본문을 스크롤한다. 모바일 높이는 85dvh와 화면 높이에서 32px을 뺀 값 중 작은 값으로 제한해 화면 안에 맞춘다. 주요 본문·제목은 데스크톱 20px·24px, 모바일 18px·22px로 읽을 수 있다. 정상 닫기 시 같은 사무실이 남아 있고 결재 등 상위 창이 없을 때 일반 보기·전체 보기 모두 지도에 포커스를 돌려준다. 경로 변경·언마운트에서는 이전 지도에 포커스를 돌려주지 않는다.
- 화면에는 방향 버튼 네 개, 상호작용, 일시정지·재개 등 꼭 필요한 조작만 제공한다. 이동·상호작용은 키보드로도 사용할 수 있으며 시작·끝내기 전환과 큰 설명 패널은 제공하지 않는다. 미니맵은 스크롤 지도의 형제 요소로 배치하고 일반·전체 보기 모두 화면 모서리에 작게 고정해 지도를 스크롤해도 따라 움직이지 않게 한다. 주변 대상·층 도착은 상태 안내로 읽고 매 이동마다 알리지 않는다. 감소된 모션에서는 이동 경로를 즉시 완료한다.
- 층 이동은 실제 hash·선택 run을 변경한다. 이전 직원 상세·선택한 결재를 정리하고 프로젝트가 바뀌면 이전 업무 일지 스냅샷도 닫는다. 결재 자체는 서버에서 답변·종료하지 않는다. 외부 결재 목록은 목적지 프로젝트의 run 전체, 지도 서류는 선택 run 범위를 유지한다. 다른 유효 층으로의 run 선택·직접 hash·뒤로 가기에서는 둘러보기를 활성화하고 엘리베이터 앞 복도에서 시작한다. 로비·로딩이 끝난 잘못된 경로에서는 사무실을 종료한다. 새로고침의 유효 층 진입도 기본 활성화한다.

### 엘리베이터 클릭 이동과 보기 모드 유지

상태: 로컬 구현. 엘리베이터 클릭 이동과 App에서 관리하는 전체 보기 모드 유지가 반영되었으며 UI 대상 검사 4개 파일·80개 테스트와 typecheck·diff 검사를 통과했으며 전체 검사·독립 리뷰·브라우저 검증은 진행 중이다. [변경 010](../changes/010-agent-check-ins.md)의 새 결과이며 기존 완료 이력과 구분한다.

엘리베이터를 클릭하면 대표가 현재 위치에서 엘리베이터까지 실제 지도 경로를 따라 이동한 뒤 층 선택 창을 연다. 도착 전에 창을 열거나 대표 위치를 순간적으로 바꿔 클릭 이동을 대신하지 않는다. 이미 도착한 위치이면 바로 열 수 있으며 감소된 모션 설정에서는 기존 클릭 이동의 모션 축소 정책을 따른다. 일반 보기·전체 보기 모두 지도 경계·벽·출입구의 기존 이동 기준을 지킨다. 가까이에서 E·Enter·상호작용 버튼으로 여는 기존 경로도 유지한다.

이동 중 수동 이동·일시정지·결재 같은 기존 중단 동작, 다른 층/run으로 전환, 대상 경로 실패가 발생하면 이전 이동의 늦은 도착 처리로 창을 열지 않는다. 경로를 찾을 수 없으면 도착이나 층 선택 성공으로 처리하지 않고 현재 위치와 실패 안내를 유지한다. 층 선택 창의 키보드 탐색·포커스·닫기와 목적지 소실 시 현재 층 유지·오류 안내는 기존 계약을 따른다.

전체 보기에서 층이나 run을 바꾸면 목적지도 전체 보기로 유지하고 일반 보기에서 바꾸면 일반 보기로 유지한다. 선택한 보기 모드는 [App](../../web/src/App.tsx)의 overviewOpen과 [Office](../../web/src/Office.tsx)의 overviewOpen/onOverviewOpenChange로 유지하되 위치·이동 경로·직원 상세·엘리베이터 창·안내 목적지 등 층별 상태는 기존 전환 규칙대로 정리한다. 목적지 도착 위치·카메라·포커스는 선택된 보기 모드에 맞춘다. 결재가 전체 보기를 닫는 기존 규칙은 유지하며 브라우저 저장소·새로고침 복원·디자인 변경은 추가하지 않는다.

검증 기준은 클릭 직후 창 닫힘→이동 경로·도착→창 열림 순서, 이미 도착한 경우, 모션 축소, 중단·경로 실패·전환 뒤 늦은 창 열림 없음, 전체/일반 모드 각각의 층·run 전환 유지, 층별 상세 초기화와 기존 결재·키보드·포커스 회귀다. 데스크톱·390×844 실제 브라우저 E2E와 Impeccable 검토가 필요하며 아직 수행한 것으로 기록하지 않는다.

### 직접 둘러보기 완료·검증 기준

벽·지도 경계, 일반 보기의 문 틈 걷기 차단과 Enter 양방향 출입, 전체 보기의 기존 문 통과, 모든 부서·직원 접근 가능성, 층 정렬과 안정적인 근접 대상 결정을 단위 테스트한다. 실제 App과 Office를 함께 렌더링해 키보드·화면 버튼, 일시정지와 창 포커스, 실제 프로젝트 이동·최신 데이터·결재 범위·업무 일지 초기화·목적지 소실 복구를 확인한다. 일반 모드·보고 갱신·감소된 모션에서 기존 동작을 보존해야 한다. 데스크톱과 390×844 실제 브라우저에서 문 통과·직원 상세·엘리베이터·카메라·모바일 컨트롤을 검증한다. 자동 검증 근거는 [이동 테스트](../../web/src/visitor.test.ts), [층 정렬 테스트](../../web/src/floors.test.ts), [Office 테스트](../../web/src/Office.test.tsx), [실제 App+Office 통합 테스트](../../web/src/VisitorIntegration.test.tsx)이며, 최종 브라우저 검증·리뷰 결과는 변경 기록에서 확인한다.

### 전체 보기·직원 보고와 단축키 검증 기준

전체 보기 전후에 같은 대표와 실제 사무실을 사용하며 축소 배치를 유지한 상태에서 방향키·WASD·화면 버튼 이동과 E·Enter 직원 상세·엘리베이터 상호작용을 검증한다. 활성화·배경 클릭·패널 닫기 후 지도 포커스, 일시정지·재개, 최상위 패널의 Esc 처리와 결재 중 입력 차단을 확인한다. 전체 보기 중에는 이동·resize 카메라 추적을 하지 않고 조작 영역을 제외한 실제 남은 지도 공간에 전체 지도가 맞아야 한다. 기존 일반 보기와 경로 전환 회귀 검사, 데스크톱·모바일 실제 브라우저 검증 결과는 변경 기록 003에 남긴다.

추가 검증: 직원 근처 J와 패널 R·J/탭 전환, 같은 프로젝트의 종료 run·완료 작업 포함 및 정확한 owner 일치, 다른 프로젝트·owner 제외, 최신 보고와 누락 값·기록 없음 표시를 확인한다. 지도 F·Space와 입력 요소·수정 키·조합·반복 이벤트 차단, 도움말 및 패널·결재 입력 소유권을 자동 테스트와 실제 브라우저에서 검증한다.

이 변경의 자동 검증은 전체 16개 파일·100개 테스트와 typecheck·build·golden·diff 검사를 통과했다. 데스크톱·모바일 브라우저에서 전체 보기 이동·실제 직원 기록·탭·단축키·엘리베이터·결재 입력 경계를 확인했다. 직원 소실·run 종료 시 포커스 복구는 두 회귀 테스트로 확인했다.

### Enter 중심 보고와 엘리베이터 키보드 탐색

현재 구현 동작이며 구현·자동 검증 결과는 [변경 기록 004](../changes/004-elevator-keyboard.md)를 따른다. 직원 근처에서 Enter를 누르면 현재 업무를 열고, 보고 안에서 다시 Enter를 누르면 작업 기록을 보여주며, 다음 Enter는 보고를 닫고 지도 포커스와 이동을 재개한다. E·J·R과 탭 전환은 선택적인 추가 조작으로 유지한다. 입력 요소·수정 키·조합 입력·반복 Enter는 이 순환을 실행하지 않으며 닫기 버튼의 기본 Enter 동작도 유지한다. 화면 도움말은 현재 맥락의 Enter 동작을 짧게 안내한다.

엘리베이터 근처 Enter로 층 선택 창을 열면 첫 번째 선택 가능한 목적지에 포커스를 두고, 목적지가 없으면 빌딩 로비 버튼에 둔다. 창 안의 위·아래 방향키로 활성 버튼 사이를 이동하며 처음과 끝에서 순환한다. 현재 층·선택 불가 목적지는 건너뛰고 닫기·로비 버튼도 탐색할 수 있다. Home·End는 각각 첫·마지막 활성 버튼으로 이동한다.

Enter·Space는 포커스된 버튼의 기본 동작으로 선택·닫기·로비 이동을 실행한다. Tab·Shift+Tab은 창 안에서 순환한다. Esc는 층 선택 창만 닫고 지도 포커스를 복구하고 이전 이동 상태로 돌아가며 전체 보기에서 열었다면 전체 보기를 남긴다. 방향키 처리는 층 선택 창 내부에 한정하고 지도 이동과 페이지 스크롤로 전파하지 않는다. 창에는 방향키·Enter 선택·Esc 닫기 중심의 짧은 안내를 표시한다.

검증 기준: 직원 현재 업무 → 기록 → 닫기·이동 재개 Enter 순환, Esc·기본 닫기와 입력·수정 키·조합·반복 Enter 차단, 첫 목적지와 목적지 없는 경우의 초기 포커스, 선택 불가 층 건너뛰기, 양방향 순환·Home·End·닫기 탐색, 기본 버튼 활성화, Tab 순환·Esc 포커스 복귀·전체 보기 유지, 실제 층 이동을 자동 테스트와 브라우저에서 확인한다. 이 후속 변경의 자동 검증은 전체 16개 파일·103개 테스트와 typecheck·build·golden·diff 검사를 통과했다. 실제 브라우저·독립 리뷰 결과는 별도 실행 기록에서 관리하며 여기서 완료를 선행 주장하지 않는다.

### 창을 닫은 뒤 연속 탐색

현재 구현과 자동 검증 결과는 [변경 기록 005](../changes/005-continuous-visitor.md)를 따른다. 직원 보고·엘리베이터를 열면 창이 열린 상태로만 배경 이동을 막고 수동 일시정지 상태는 바꾸지 않는다. 보고 창에는 Esc 닫기 안내를 표시한다. Esc는 해당 보고 창만 닫고 전체 보기를 유지한다. Esc·닫기 버튼·보고 Enter 완료는 창을 닫고 지도에 포커스를 돌려주어, 창을 열기 전 걷고 있었다면 별도 재개 없이 계속 이동할 수 있다. 층 이동 성공도 도착 후 이동을 계속하며 실패하면 선택 창과 오류 안내를 유지한다.

Space·일시정지 버튼으로 정지한 상태와 결재를 연 뒤 정지는 자동 해제하지 않는다. 전체 보기 안의 창 닫기는 전체 보기를 유지한다. 방 바로가기를 선택하면 이동 중인 목적지를 바꾸고, 일시정지 상태에서는 둘러보기를 다시 시작한다. 검증은 직원 보고·엘리베이터의 열기/닫기/Enter 완료 후 이동, 실제 층 이동 성공·실패, 수동 정지·결재 정지 보존과 지도 포커스 복귀를 포함한다. 중앙 보고 모달까지 포함한 최종 전체 16개 파일·105개 테스트와 typecheck·build·golden·diff 검사를 통과했다. 실제 브라우저·최종 독립 리뷰 결과는 별도 실행 기록에서 관리하며 완료를 선행 주장하지 않는다.

직원 보고의 중앙 모달 확장은 변경 005에 구현했다. 현재 업무·기록을 넓은 영역에서 읽는 것을 우선하며 제목·닫기·Esc 안내와 보고 전환은 모달 안에 둔다. 배경 이동을 차단하고 Esc는 이 보고만 닫아 전체 보기와 이전 이동 상태를 복구한다. 보고 Enter 현재 업무 → 기록 → 닫기 흐름도 유지한다.


### 복도·출입문과 위치 안내

현재 변경 006의 요구사항이며 구현·최종 검증 결과는 [변경 기록 006](../changes/006-door-corridor.md)에 기록한다. 일반 보기는 복도 → 문 가까이에서 Enter → 해당 팀 방 하나 → 출구에서 Enter → 같은 문 바깥 복도 순서다. 복도에는 닫힌 방 외관·문·팀 방향 표지·엘리베이터를 보여주고 다른 팀 내부와 직원·책상·말풍선·서류·도장·결재 표시는 감춘다. 방 안에서는 해당 방의 실제 내용과 출구만 보여준다. 기존 전역 좌표와 실제 부서·직원 데이터를 공유하며 방별 가상 데이터나 별도 좌표계를 만들지 않는다.

걷기는 현재 복도 또는 방의 경계를 넘지 않는다. 문은 올바른 쪽에서 가까이 접근했을 때만 동작하며 반복 Enter, 패널·결재 중 입력은 출입을 실행하지 않는다. 출입 직후 위치와 카메라를 함께 맞추고, 하단 임시 역할 방을 포함한 모든 문에서 지도 경계 안의 안전한 위치로 왕복한다. 직원 보고 Enter 현재 업무 → 기록 → 닫기와 Esc 후 이전 걷기 상태 복귀, 엘리베이터 키보드 탐색, 명시적 일시정지·결재 포커스는 유지한다.

현재 위치 이름, 실제 문 위치에서 계산한 팀 방향 표지, 대표의 실제 위치와 현재 방·진행 중 목적지를 표시하는 작은 미니맵을 제공한다. 미니맵은 스크롤 지도와 분리해 일반·전체 보기에서 화면 모서리에 고정한다. 상단 부서 바로가기, 방 제목 버튼, 지도 문 버튼은 선택한 방 안까지 대표를 걷게 하며 방향 안내만 바꾸지 않는다. 미니맵은 위치 안내용이며 클릭 이동을 제공하지 않는다. 모바일에서도 위치·표지·미니맵과 이동 컨트롤을 읽을 수 있어야 한다. 방 바로가기 이동과 축약 UI의 구현·자동 검증 및 남은 독립 검수는 [변경 013](../changes/013-room-navigation.md)을 따른다.

전체 보기는 기존 열 개 방과 실제 직원의 전체 지도를 유지한다. F 전환은 대표 위치를 보존하고 전체 보기의 이동·상호작용을 유지한다. 부서 바로가기와 지도 버튼은 전체 보기에서도 방 안까지 걷는다. 일반 보기로 돌아오면 실제 좌표로 현재 방 또는 복도를 결정하여 문 경계에 갇히지 않아야 한다.

검증 기준: 모든 문 바깥 복도 접근과 Enter 왕복, 문 틈 걷기 차단, 방별 표시·상호작용 범위, 방향 안내와 미니맵 좌표 일치, 전체 보기 전환 위치 보존을 자동 검증한다. 방 바로가기·문·방 제목 버튼의 모든 방 경로, 재지정·취소·일시정지 중 새 목적지 선택·경로 실패도 자동 검증하며 실제 브라우저 결과는 변경 013에 따로 기록한다. 지연된 직접 URL 로딩·로비 재진입을 확인한다. 1440×900 데스크톱과 390×844 모바일 실제 브라우저에서 복도 → 입장 → 실제 직원 보고 → Esc → 퇴장 → 복도를 확인하고 화면 가로 넘침·전체 보기·포커스를 검증한다. 보강 후 최종 전체 18개 파일·120개 테스트와 typecheck·build·golden·diff 검사를 통과했다. 2026-10-20 R1 실제 데스크톱·모바일 E2E와 Impeccable 리뷰는 PASS다. 초기 로딩 실패 후 재시도 활성화 의도, 화면 버튼 Enter 반복 차단, J 기록 열기의 문 우선순위 등 R1 코드 리뷰 필수 보강 3건을 확인했고 모두 수정 완료했다. 수정 후 최종 동일본 검토는 실행 진행 기록에서 관리한다.
