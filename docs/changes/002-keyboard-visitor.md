# 002 — 키보드 직접 둘러보기와 프로젝트 엘리베이터

상태: 완료. 구현과 후속 수정의 자동 검증·실제 브라우저 검증·독립 리뷰 통과.

## 이유와 범위

기존 대표 캐릭터로 사무실을 직접 걸으며 실제 직원의 보고를 살펴보고 엘리베이터로 다른 실제 프로젝트 층을 방문한다. 방향키·WASD, E·Enter, Esc·일시정지·재개, 화면 방향·상호작용 버튼을 제공한다. 벽·문과 충돌 계산을 일치시키고 지도 안 카메라와 창별 포커스를 관리한다.

실제 프로젝트·run과 owner·최신 작업·model·effort를 사용한다. 결재·기획서·업무 일지·기존 경로와 일반 관찰을 보존한다. 프런트엔드만 확장하며 서버·DB·API·인증·설정, 의존성 추가, 에이전트 실행, 가상 업무 데이터와 게임 엔진은 범위 밖이다. 디자인 원칙은 변경하지 않는다.

## 검증 방법과 결과

후속 수정 후 자동 검증: 이동 경계·문 통과·모든 부서 접근·층 정렬 단위 테스트와 실제 App+Office 통합 테스트를 포함해 전체 15개 파일·93개 테스트 통과. 리더가 `npm run typecheck`, `npm run build`, 원본 progress.py golden 비교와 `git diff --check` 통과를 확인했다. 독립 lint 스크립트는 없다.

R1 지적 반영: 화면 안 지도 높이·대표 표시 영역 기준 카메라, 전체 보기 배치·일시정지·포커스 복귀, 일시정지 중 resize 추적 차단, 실제 직원 상세·최신 메타데이터와 실제 App 경로 전환 테스트를 보강했다.

R2 지적 반영: 지도 위치가 화면 아래로 내려가도 높이를 유지하고 일반 페이지 스크롤·패널 배치 변경 후 다시 측정한다. 새 층 도착 카메라는 목적지 지도 높이 반영 뒤 맞춘다. 실제 직원 상세 → 전체 보기 → 결재 창의 포커스 소유권과 전환 검증을 보강했다. 화면 아래 지도·스크롤 후 높이 복구와 새 층 도착 카메라 테스트를 포함해 위 전체 자동 검증을 통과했다.

R3 지적 반영: 감소된 모션의 전역 전환 시간 설정이 지도 높이 변경에도 적용되어 새 층 도착 카메라가 중간 높이를 읽는 원인을 확인했다. 둘러보기 지도에 `transition: none`을 명시하고 회귀 테스트를 추가했다. 디자인 원칙은 변경하지 않았다.

실제 브라우저 검증: 격리된 localhost:4781 환경에서 문까지 67회 키 이동·벽 차단·직원 상세와 최신 보고·실제 프로젝트 엘리베이터 이동·현재/빈 층 선택 차단·종료 run과 뒤로 가기·결재 중 이동 차단을 확인했다. 전체 보기의 10개 부서 맞춤·Esc 후 일시정지·포커스 복귀·일시정지 중 resize와 390×500에서 일반 페이지 스크롤 후 지도 복구도 확인했다.

최종 도착 검증: 감소된 모션을 실제 적용한 1440×900과 390×844에서 양방향 층 이동 네 건, 일반 모션의 390×844에서 한 건을 새로 실행했다. 다섯 도착 모두 추가 이동·재개 없이 대표 전체가 지도와 화면 안에 보였고, 지도 애니메이션은 없으며 지정 높이와 계산·실측 높이가 일치했다. 상세 증거는 `.omc/plans/e2e-visitor-final-results.md`에 남겼다. 최종 독립 리뷰는 Karpathy·Ponytail·Impeccable·E2E 모두 PASS다.

검증 한계: 네이티브 키를 길게 누르는 반복 입력과 실제 결재 창이 열린 상태의 resize는 브라우저에서 별도 재현하지 않았으며 자동 테스트로 확인했다. 마지막 도착 재검증은 위 다섯 건이며 일반 모션 데스크톱 양방향을 별도로 반복하지 않았다.
