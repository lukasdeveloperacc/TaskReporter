# 007 — Building 층 숨김·복원

상태: 구현·자동 검증 완료. 독립 리뷰·브라우저 검증의 revision별 결과는 실행 진행 기록에서 관리한다.

## 이유와 범위

프로젝트 기록을 남긴 채 Building의 층 목록을 정리한다. 프로젝트 단위 숨김·복원과 숨긴 층 관리, 모두 숨김 상태의 복구 경로를 제공한다. Building과 직접 둘러보기의 엘리베이터 목록에서 숨긴 층을 제외한다. 기존 전체 정렬 후 필터링하여 숨김·복원으로 다른 층 번호가 바뀌지 않게 한다.

SQLite projects.hidden을 추가하고 기존 DB에는 열 유무를 확인해 추가한다. 새로고침·재시작 후 상태를 유지하며 report/upsert·신규 run으로 자동 복원하지 않는다. 프로젝트·run·질문/답변·기획서 연결과 실제 파일은 보존한다. 전체 상태 snapshot과 직접 링크 접근은 유지한다. 숨긴 프로젝트의 pending 질문도 로비에서 열고 답할 수 있다.

`PATCH /api/projects/visibility`의 입력 검증·404·저장 실패와 SSE 갱신, 화면의 오류·재시도를 처리한다. 영구 삭제·자동 숨김·일괄 숨김·신규 의존성은 제외한다. 숨김은 접근 제어 기능이 아니다.

## 구현 작업

- Backend: 공용 ProjectView.hidden과 API, DB 기본값·기존 DB 변경·upsert 보존, snapshot·report·질문 보존 및 SSE 테스트.
- Frontend: 번호 계산 뒤 숨김 필터, 층 메뉴·숨긴 층 관리·복원·모두 숨김 안내, 요청 오류·중복 요청 방지, 숨긴 pending 질문 응답과 엘리베이터의 최신 상태 확인.
- Docs: 요구사항·저장 정책·사용자 흐름 및 이 변경 기록을 실제 반영 결과와 일치시킨다.

## 검증 기준과 결과

리더가 전체 자동 검사 결과를 확인했다. `npm test`는 18개 파일·153개 테스트를 통과했고, `npm run typecheck`, `npm run build`, `git diff --check`도 통과했다. 별도 lint 스크립트는 없다.

기존 DB의 보존 마이그레이션·재개방·새 report 뒤 숨김 유지·기록/질문 보존, API의 400/404/200·SSE, 층 번호 유지·숨김/복원·실패 복구와 엘리베이터 제외를 자동 검증했다. 임시 DB·서버를 사용하여 한국어·기존 밝은 테마의 데스크톱 1440×900과 모바일 390×844에서 층 메뉴, 혼합 상태 관리·복원, 모두 숨김 복구, 숨긴 프로젝트 질문 열기·답변, 저장 실패·재시도, 엘리베이터 목록을 브라우저로 확인한다. 실제 사용자 DB는 수정하지 않는다.

`npm run golden -- <설치된 basic-team 경로>`는 종료 코드 0을 반환했지만 설치본의 현재 예제는 11개 작업이고 저장소의 고정 예제는 17개 작업이므로 예제 출력끼리의 동등성을 주장하지 않는다. 별도 비교로 설치본 원본 Python `progress.apply`에 저장소의 동일한 `progress-example.md`를 재생하여 기대 결과의 17개 작업·8개 리뷰가 정확히 일치함을 확인했다. TypeScript의 동일 fixture 재생도 전체 테스트에 포함해 통과했다. 설치본 예제 변경에 따른 차이는 이번 기능과 무관하며 비교 스크립트 자체는 변경하지 않았다.

Backend/Frontend 도메인 및 Karpathy·Ponytail·Impeccable·E2E 독립 리뷰와 브라우저 검증의 revision별 결과는 실행 진행 기록에서 관리한다. 위 자동 검사가 브라우저·독립 리뷰 완료를 대신하지 않는다.
