# 004 — Enter 중심 업무 보고와 엘리베이터 키보드 탐색

상태: 완료(구현·자동 검증 범위). 실제 브라우저·최종 독립 리뷰 판정은 별도 실행 기록에서 관리한다.

## 이유와 범위

직원 보고는 Enter만으로 현재 업무 → 작업 기록 → 닫기·이동 재개 순서로 확인한다. 마지막 Enter는 지도 포커스와 이동을 재개하며 Esc·닫기 버튼의 기존 닫기·일시정지는 유지한다. E·J·R·탭은 선택적인 추가 조작이며 맥락에 맞는 Enter 도움말을 짧게 제공한다. 입력 요소·수정 키·조합 입력·반복 Enter를 소비하지 않고 닫기 버튼의 기본 Enter 동작도 유지한다.

엘리베이터 근처 Enter로 창을 열고 방향키로 목적지를 고른 뒤 Enter로 실제 층을 이동한다. 창 내부 위·아래 방향키는 현재 층·비활성 목적지를 건너뛰어 활성 버튼의 포커스를 순환시키고 Home·End는 처음·마지막 활성 버튼으로 이동한다. 닫기·빌딩 로비도 탐색 대상이다. 초기 포커스는 첫 선택 가능한 목적지이며 없으면 로비 버튼이다.

Enter·Space의 기본 버튼 동작, Tab·Shift+Tab의 창 내부 순환과 Esc 닫기를 유지한다. Esc는 이 창만 닫고 지도 포커스와 일시정지를 유지하며 전체 보기에서 열었다면 전체 보기를 닫지 않는다. 눈에 보이는 키보드 안내를 제공한다. 기존 실제 프로젝트·run 선택 경계를 유지하고 서버·API·DB·의존성·디자인 원칙은 변경하지 않는다. 완료된 변경 003은 당시 기록으로 보존한다.

## 구현과 검증

- 구현 완료: 직원 보고 Enter 현재 업무·기록·닫기와 지도 포커스·이동 재개, 기존 Esc·닫기 동작 보존.
- 구현 완료: 층 선택 창 내부 방향키·Home/End 탐색, 첫 목적지 초기 포커스와 안내.
- 자동 검증: 직원 보고 Enter 순환·마지막 이동 재개, Esc·기본 닫기 일시정지, 입력·수정 키·조합·반복 Enter 차단, 비활성·현재 층 건너뛰기, 양방향 순환·닫기·로비 탐색, 목적지 없는 경우, Enter·Space 기본 동작, Tab 순환·Esc 포커스 복귀·일시정지·전체 보기 유지 및 실제 층 이동.

전체 16개 파일·103개 테스트 통과. 리더가 `npm run typecheck`, `npm run build`, 설치된 원본 basic-team을 인자로 지정한 golden 비교와 `git diff --check` 통과를 확인했다. 이 수치는 이번 후속 변경을 포함한 새 전체 검사 결과다.

실제 브라우저와 독립 리뷰의 결과는 별도 실행 기록에서 관리하며 완료를 선행 주장하지 않는다.
