# 직원 대기 상태 구분

상태: 완료. 로컬 구현·자동 검사·격리 브라우저 검증 완료. 실행 중인 4780 서버 배포는 별도다.

## 이유와 범위

완료 후 쉬는 직원과 첫 작업을 기다리는 직원이 모두 `대기`로 보여 진행 상황을 구분하기 어려웠다. 보고된 작업과 완료 기록을 기준으로 말풍선·직원 상세의 상태 문구를 함께 바꾼다. 기존 최근 완료 제목, 캐릭터 배치와 이동 상태는 유지한다. MCP 계약과 스킬은 변경하지 않는다.

- 대기 작업만 있음: `시작 대기`
- 완료 기록과 대기 작업 있음: `다음 작업 대기`
- 완료 기록 있음, 대기 작업 없음: `완료 후 대기`
- 위 조건 없이 중단 작업 있음: `작업 중단`
- 위 조건 없음: `업무 미보고`

진행중 작업, 지연 보고, 종료 실행의 상태가 위 대기 구분보다 우선한다. 현재 업무 미보고를 근거 없이 시작 전으로 판단하지 않는다.

## 구현과 검증

`buildOffice`에서 상태 문구를 한 번 결정해 말풍선과 상세에 전달한다. 완료·첫 작업·다음 작업·중단·미보고·종료 분기와 완료 직원 상세 표시를 자동 검사한다. 관련 요구사항은 [진행 보고와 사무실](../requirements/progress-office.md)에 반영한다.

검증 결과: 전체 테스트 259개, 타입 검사, 프로덕션 빌드 통과. 격리 DB와 4781 서버에 실제 MCP로 합성 상태를 보고하고 1185×800 브라우저에서 `완료 후 대기`·`시작 대기`·`다음 작업 대기`와 최근 완료 제목이 함께 표시되는 것을 확인했다. Impeccable 감지 결과는 빈 배열이다. 증거는 로컬 `.omx/reports/office-status-20261024/`에 보관한다.
